## Risks & open questions
- **Environment (`./scripts/doctor` verdict)**: All step prerequisites met (`ok prerequisite met: ./gradlew -v (steps: test, lint, build)`; `ok profile fast: runnable on this machine`; `ok profile full: runnable on this machine`; `== result: 0 fail, 1 warn ==`). Note: in the agent runner, Gradle daemon loopback sockets require running `./scripts/check` with `BypassSandbox: true`.
- **Risk 1: `AccessibilityService.dispatchGesture` requires `android:canPerformGestures="true"`**:
  - *Context*: Without `android:canPerformGestures="true"` in `accessibility_service_config.xml`, Android silently refuses programmatic gestures at runtime.
  - *Recommendation*: Enable `android:canPerformGestures="true"` in `app/src/main/res/xml/accessibility_service_config.xml` and enforce it in `ManifestVerificationTest.kt`.
  - *Rationale*: Guarantees the OS grants gesture capability when the user enables the accessibility service.
- **Risk 2: Deterministic testing of `400 ms` delayed skip and cancellation**:
  - *Context*: Relying on real wall-clock `Handler.postDelayed` sleeps in unit tests can cause flakiness.
  - *Recommendation*: Inject a lightweight clock (`() -> Long`) and delayed-task scheduler interface into `SkipperAccessibilityService` (defaulting to `SystemClock.uptimeMillis` and main-thread `Handler` in production).
  - *Rationale*: Allows fast, deterministic unit and Robolectric tests for `AC-4`, `AC-5`, and `AC-6` without real thread sleeps.
