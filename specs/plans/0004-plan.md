## Risks & open questions
- **Environment (`./scripts/doctor` verdict)**: All step prerequisites met (`ok prerequisite met: ./gradlew -v (steps: test, lint, build)`; `ok profile fast: runnable on this machine`; `ok profile full: runnable on this machine`; `== result: 0 fail, 1 warn ==`).
- **Risk 1: Process residue (`./scripts/residue`) from third-party Gradle worker daemons when updating `scripts/check.conf`**:
  - *Context*: Third-party Gradle wrapper plugins for Ktlint often spawn persistent Gradle Worker API daemons that survive `--no-daemon` builds and fail `./scripts/residue`.
  - *Recommendation*: Run official `com.pinterest.ktlint:ktlint-cli:1.4.1` and `io.gitlab.arturbosch.detekt:detekt-cli:1.23.7` via detached Gradle configurations and synchronous `JavaExec` tasks (`ktlintCheck` and `detekt`), matching the existing `robolectricSdkJars` detached-configuration pattern in `app/build.gradle.kts`.
  - *Rationale*: Executes synchronously in short-lived child JVMs that terminate immediately on task completion, guarantees zero runtime APK dependency leakage (`INV-1`), and keeps `./scripts/residue` and `./scripts/residue --fast` clean (`AC-5`).
- **Risk 2: Default Ktlint/Detekt rules conflicting with Jetpack Compose `@Composable` PascalCase and existing conventions**:
  - *Context*: Standard Kotlin naming rules flag `@Composable` PascalCase functions (`HomeScreen`, `KeywordsCard`) and defensive `catch (_: RuntimeException)` blocks required by `docs/conventions.md` for Accessibility Service resilience.
  - *Recommendation*: Configure `ktlint_function_naming_ignore_when_annotated_with = Composable` in `.editorconfig` and `ignoreAnnotated: ['Composable']` / aligned thresholds in `config/detekt/detekt.yml` while keeping real bug, formatting, unused-code, and complexity checks active.
  - *Rationale*: Aligns static analysis with `docs/conventions.md` without false positives on idiomatic Jetpack Compose or fail-safe Accessibility Service code.
