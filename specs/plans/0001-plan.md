## Risks & open questions
- **Risk 1: Local Java Runtime / Android SDK availability (R-13 environment gap)**:
  - *Context*: On macOS, system `java` is not linked to PATH by default and `JAVA_HOME` was pointing to a non-existent `@25` path, though OpenJDK 26 is installed at `/opt/homebrew/opt/openjdk/bin/java`. Furthermore, local Android SDK tools may require downloading platforms/build-tools during initial Gradle invocation or rely on GitHub Actions CI runner.
  - *Recommendation*:
    1. Set `JAVA_HOME=/opt/homebrew/opt/openjdk` in wrapper/check commands or system profile.
    2. Ensure `scripts/check.conf` prerequisites check for a runnable Java installation.
    3. Configure GitHub Actions CI (`.github/workflows/check.yml`) with pre-installed Android SDK and Temurin JDK 17/21 so CI always achieves full green.
- **Risk 2: AGP compatibility with Java 25/26**:
  - *Context*: Android Gradle Plugin 8.7 officially supports JDK 17 and JDK 21. Java 26 (early access / cutting-edge) might trigger a Gradle warning or incompatibility if bytecode targeting is not constrained.
  - *Recommendation*: Explicitly pin `jvmToolchain(17)` or `jvmToolchain(21)` in `app/build.gradle.kts` so Gradle toolchain handles bytecode compatibility predictably.
